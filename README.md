# Лабораторная работа №3. Консольное приложение для управления газотранспортной сетью

Это консольное приложение на C++, разработанное для управления объектами трубопроводной системы: трубами и компрессорными станциями (КС). Проект является развитием предыдущих работ и реализует более сложную логику, включая построение и анализ графовой структуры сети.

## 📜 О проекте

Приложение позволяет в интерактивном режиме создавать объекты, объединять их в направленную сеть, просматривать, удалять и редактировать. Данные могут быть сохранены в файл для последующей загрузки. Все действия пользователя записываются в лог-файл.

Проект демонстрирует понимание и применение ключевых концепций C++, таких как классы, инкапсуляция, полиморфизм, шаблоны, контейнеры STL (`std::map`) и работа с графовыми алгоритмами.

## ✨ Ключевые возможности

*   **Управление объектами:** Добавление, просмотр и удаление неограниченного количества труб и КС.
*   **Построение сети:** Возможность соединять компрессорные станции трубами, формируя направленный граф.
*   **Топологическая сортировка:** Реализован алгоритм топологической сортировки для построенного графа сети, позволяющий выявить порядок выполнения зависимых операций.
*   **Целостность графа:** При удалении трубы или КС, все связанные с ними соединения в сети автоматически и безопасно разрываются, что предотвращает появление "висячих" ребер и неконсистентных состояний в графе.
*   **Фильтрация и поиск:**
    *   Поиск труб по названию или по статусу "в ремонте".
    *   Поиск КС по названию или по проценту незадействованных цехов.
*   **Пакетное редактирование:** Возможность изменить статус или удалить сразу несколько найденных объектов.
*   **Сохранение и загрузка:** Персистентное хранение данных (включая структуру сети) в текстовом файле.
*   **Логирование действий:** Все операции, выбранные пользователем, записываются в файл `log.txt`.

## 📂 Структура проекта

Проект имеет модульную структуру, где каждый класс вынесен в отдельные заголовочные (`.h`) и файлы реализации (`.cpp`).

*   `main.cpp`: Точка входа в программу. Содержит главный цикл и отображение меню.
*   `Manager.h / Manager.cpp`: "Мозг" приложения. Класс-контроллер, который управляет всей логикой, хранит объекты в `std::map` и обрабатывает команды пользователя.
*   `Pipe.h / Pipe.cpp`: Класс, описывающий модель данных для сущности "Труба".
*   `CS.h / CS.cpp`: Класс, описывающий модель данных для "Компрессорной станции", включая информацию о её соединениях.
*   `Utils.h / Utils.cpp`: Вспомогательные утилиты, включая `Logger` и шаблонную функцию для безопасного ввода `getValidInput<T>`.
*   `theory.md`: Детальное описание теоретических аспектов кода, архитектуры и примененных алгоритмов.
*   `log.txt`: Файл, в который автоматически записываются логи работы программы.

## 🚀 Сборка и запуск

### Требования

*   Компилятор C++ с поддержкой стандарта C++11 или выше (например, g++).

### Компиляция

1.  Поместите все файлы (`.h`, `.cpp`) в одну директорию.
2.  Откройте терминал или командную строку в этой директории.
3.  Выполните следующую команду для компиляции (результат будет в папке `bin`):
    ```bash
    g++ main.cpp Manager.cpp Pipe.cpp CS.cpp Utils.cpp -o bin/pipeline_manager.exe
    ```

### Запуск

После успешной компиляции в директории `bin` появится исполняемый файл `pipeline_manager.exe`. Запустите его командой:

```bash
./bin/pipeline_manager.exe
```

## ⚙️ Детали реализации

### Топологическая сортировка (Алгоритм Кана)

В коде реализован **алгоритм Кана** для топологической сортировки графа компрессорных станций. Идея алгоритма заключается в том, чтобы обрабатывать вершины (КС) в таком порядке, чтобы все зависимости были выполнены. Алгоритм работает следующим образом:

1.  **Подсчет "входящих степеней" (`in-degree`)**
    *   Для каждой КС подсчитывается, сколько в нее входит труб (ребер). Для этого сначала счетчики всех КС обнуляются, а затем код проходит по всем соединениям в графе и увеличивает счетчик для каждой целевой КС.

2.  **Создание очереди и поиск стартовых вершин**
    *   Создается очередь, в которую помещаются все КС, у которых входящая степень равна 0. Это "стартовые" вершины, которые не зависят от других.

3.  **Основной цикл обработки**
    *   Пока очередь не пуста, из нее извлекается первая КС и добавляется в итоговый отсортированный список.
    *   Далее, программа "удаляет" эту КС из графа, мысленно обходя все ее исходящие соединения. У каждой соседней КС, в которую вела труба, счетчик входящих степеней уменьшается на 1.
    *   Если у какой-либо из соседних КС счетчик становится равен нулю, это значит, что все ее зависимости выполнены, и она добавляется в очередь для дальнейшей обработки.

4.  **Проверка на циклы**
    *   После завершения цикла, если размер итогового отсортированного списка меньше общего количества станций, это означает, что в графе есть цикл. В таком случае топологическая сортировка невозможна, и программа выводит ошибку.
    *   В противном случае, на экран выводится отсортированный список.
