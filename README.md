# Лабораторная работа №2. Консольное приложение для управления трубопроводной системой

Это консольное приложение на C++, разработанное для управления объектами трубопроводной системы: трубами и компрессорными станциями (КС). Проект является развитием предыдущей работы и реализует более сложную логику с использованием объектно-ориентированного подхода.

## 📜 О проекте

Приложение позволяет в интерактивном режиме добавлять, просматривать, удалять и редактировать множество объектов. Данные могут быть сохранены в файл для последующей загрузки. Все действия пользователя записываются в лог-файл для отладки и анализа.

Проект демонстрирует понимание и применение ключевых концепций C++, таких как классы, инкапсуляция, работа с потоками ввода/вывода, шаблоны и модульная организация кода.

## ✨ Ключевые возможности

  * **Управление объектами:** Добавление, просмотр и удаление неограниченного количества труб и КС.
  * **Уникальная идентификация:** Каждому новому объекту автоматически присваивается уникальный ID.
  * **Фильтрация и поиск:**
      * Поиск труб по названию или по статусу "в ремонте".
      * Поиск КС по названию или по проценту незадействованных цехов.
  * **Пакетное редактирование:** Возможность изменить статус ("в ремонте" / "в эксплуатации") сразу у нескольких найденных труб.
  * **Сохранение и загрузка:** Персистентное хранение данных в текстовом файле, формат которого задается пользователем.
  * **Логирование действий:** Все операции, выбранные пользователем, записываются в файл `log.txt` с меткой времени.

## 📂 Структура проекта

Проект имеет модульную структуру, где каждый класс вынесен в отдельные заголовочные (`.h`) и файлы реализации (`.cpp`) для лучшей читаемости и поддержки.

  * `main.cpp`: Точка входа в программу. Содержит главный цикл и отображение меню.
  * `Manager.h / Manager.cpp`: "Мозг" приложения. Класс-контроллер, который управляет всей логикой, хранит списки объектов и обрабатывает команды пользователя.
  * `Pipe.h / Pipe.cpp`: Класс, описывающий модель данных для сущности "Труба".
  * `CS.h / CS.cpp`: Класс, описывающий модель данных для сущности "Компрессорная станция".
  * `Utils.h / Utils.cpp`: Вспомогательные утилиты, включая класс `Logger` и шаблонную функцию для безопасного ввода `getValidInput<T>`.
  * `log.txt`: Файл, в который автоматически записываются логи работы программы.
  * `data.txt` (пример): Файл, в который пользователь может сохранить данные.

## 🏛️ Детальный разбор кода

Проект имеет модульную структуру. Это означает, что код не свален в один большой файл, а логически разделен на несколько частей. Это стандартная практика в профессиональной разработке, которая делает код более читаемым, поддерживаемым и позволяет легко использовать его повторно.

### 📜 Заголовочные файлы (`.h`) vs Файлы реализации (`.cpp`)

* **Заголовочные файлы (`.h`):** Это "оглавление" или "интерфейс" нашего кода. Они говорят, *что* существует в программе (какие классы, какие у них есть методы), но не говорят, *как* это работает. Другие файлы могут `#include` "заголовок", чтобы узнать о существовании нужного им класса.
* **Файлы реализации (`.cpp`):** Это "главы книги". Здесь находится сам код, который реализует то, что было обещано в заголовочных файлах.

### Отдельно про каждый файл

#### `Utils.h` — Заголовочный файл утилит

Этот файл объявляет вспомогательные инструменты, которые используются во всем проекте.

* `#ifndef UTILS_H`, `#define UTILS_H`, `#endif // UTILS_H`: Это **стражи включения** (include guards). Они гарантируют, что если этот файл будет случайно подключен несколько раз в одном месте, его содержимое будет вставлено в код только один раз. Это предотвращает ошибки компиляции. `UTILS_H` — это уникальный идентификатор для этого файла.
* `#include <...>`: Подключение стандартных библиотек C++. Например, `<iostream>` для ввода/вывода, `<string>` для строк, `<fstream>` для работы с файлами, `<sstream>` для работы со строками как с потоками.
* `class Logger { ... };`: **Объявление** класса `Logger`. Мы говорим: "Существует такой класс".
* `public:`: Эта секция объявляет члены класса, доступные из любой части программы. Это публичный интерфейс.
* `Logger(const std::string& filename);`: **Конструктор** класса. Это специальный метод, который вызывается при создании объекта. `const std::string&` означает, что мы принимаем имя файла по *константной ссылке* — это быстро (не создается копия строки) и безопасно (мы обещаем не менять исходное имя файла).
* `private:`: В этой секции находятся члены класса, доступные только изнутри самого класса `Logger`. Это пример **инкапсуляции**.
* `std::ofstream logfile;`: Поле класса. `ofstream` — это "output file stream" (поток вывода в файл). Этот объект будет управлять записью в наш лог-файл.
* `template<typename T>`: Объявление **шаблона**. Это позволяет нам написать одну функцию, которая может работать с разными типами данных (`int`, `double` и т.д.). `T` — это имя-заменитель для типа.
* `T getValidInput(...)`: Объявление нашей шаблонной функции для безопасного ввода.
* `template<> std::string getValidInput<std::string>(...);`: **Специализация шаблона**. Мы говорим компилятору, что для типа `std::string` нужно использовать не общую шаблонную версию, а специальную, реализация которой будет в `.cpp` файле.

#### `Utils.cpp` — Реализация утилит

Здесь находится код, который выполняет то, что было обещано в `Utils.h`.

* `#include "Utils.h"`: Подключаем заголовочный файл, чтобы компилятор знал, что мы собираемся реализовывать.
* `#include <chrono>` и `#include <iomanip>`: Библиотеки для работы со временем и его форматированием.
* `Logger::Logger(...)`: **Реализация конструктора**. `Logger::` указывает, что мы определяем член класса `Logger`.
* `logfile.open(filename, std::ios::app);`: Метод `open` открывает файл. `std::ios::app` (append) — это флаг, который означает "открывать в режиме дозаписи в конец".
* `if (!logfile.is_open())`: Проверка, удалось ли открыть файл.
* `std::cerr`: Стандартный поток для вывода ошибок.
* `void Logger::log(...)`: Реализация метода логирования.
* `auto now = ...`: Ключевое слово `auto` говорит компилятору самому определить тип переменной. Это удобно для сложных типов, как те, что используются в `<chrono>`.
* `std::put_time(...)`: Функция для форматирования времени в заданный строковый формат (например, `"дд-мм-гггг чч:мм:сс"`).

#### `Pipe.h` / `CS.h` — Заголовочные файлы моделей

Эти файлы очень похожи. Они описывают наши "модели данных" — классы `Pipe` и `CS`.

* `private: int id; ...`: Поля класса. Они скрыты от прямого доступа.
* `public: Pipe();`: **Конструктор по умолчанию**. Создает "пустой" объект.
* `Pipe(int id, ...);`: **Перегруженный конструктор**. Позволяет создать объект и сразу задать ему все параметры. Идеально для загрузки из файла.
* `int getId() const;`: **Геттер**. Метод для получения значения приватного поля. `const` в конце означает, что этот метод не изменяет объект. Это важно для безопасности кода.
* `void setRepairStatus(bool status);`: **Сеттер**. Метод для изменения приватного поля.
* `friend std::ostream& operator<<(...);`: Объявление **дружественной функции**. Эта функция не является частью класса, но ей дается доступ к его `private` полям. Это необходимо, чтобы мы могли "научить" оператор `<<` выводить наш объект в консоль (`std::cout << my_pipe;`).
* `static Pipe createPipe(int new_id);`: Объявление **статического метода**. Этот метод принадлежит классу в целом, а не конкретному объекту. Его можно вызвать как `Pipe::createPipe(...)`. Он используется как "фабрика" для создания новых объектов с пользовательским вводом.

#### `Pipe.cpp` / `CS.cpp` — Реализация моделей

Здесь находится код для методов классов `Pipe` и `CS`.

* `Pipe::Pipe() : id(0), ... {}`: **Список инициализации конструктора**. Это более правильный и эффективный способ задать начальные значения полям, чем присваивать их в теле конструктора `{}`.
* `double CS::getUnusedPercent() const`: Пример метода, который выполняет вычисления на основе данных объекта.
* `(double)(...)`: **Явное приведение типа**. Если делить целое число на целое, результат тоже будет целым (дробная часть отбросится). Чтобы получить точный результат, мы временно "превращаем" одно из чисел в `double`.
* `Pipe::createPipe(int new_id)`: Реализация фабричного метода. Он создает пустой объект, запрашивает у пользователя все данные с помощью `getValidInput` и логических проверок в цикле `while`, а затем возвращает полностью готовый объект.

#### `Manager.h` — Заголовочный файл главного контроллера

Это "пульт управления" всей программой.

* `#include <vector>`: Подключение **вектора**. `std::vector` — это динамический массив из стандартной библиотеки. Он может хранить сколько угодно объектов и автоматически управляет памятью.
* `std::vector<Pipe> pipes;`: Поле, которое будет хранить все наши объекты-трубы.
* `private: std::vector<int> findPipeIndices...`: **Вспомогательные приватные методы**. Они нужны для внутренней работы менеджера (например, для поиска), но не должны быть доступны из `main.cpp`.

#### `Manager.cpp` — Реализация главного контроллера

Самый большой файл, содержащий всю логику.

* `pipes.push_back(...)`: Метод вектора, который добавляет новый элемент в его конец.
* `for (const auto& p : pipes)`: **Range-based for loop**. Самый современный и безопасный способ перебрать все элементы в контейнере (например, в векторе). `const auto& p` означает: "для каждого элемента создай константную ссылку `p`". Ссылка `&` используется для эффективности (чтобы не копировать тяжелый объект), а `const` — для безопасности (чтобы случайно не изменить его).
* `for (auto it = pipes.begin(); ...)`: Классический цикл с **итератором**. `it` — это объект, похожий на указатель, который может "ходить" по элементам вектора. `pipes.begin()` — итератор на начало, `pipes.end()` — на позицию *после* конца. `++it` — переход к следующему элементу.
* `pipes.erase(it)`: Метод вектора для удаления элемента, на который указывает итератор.
* `std::stringstream ss(selection);`: Создание строкового потока из строки. Это позволяет нам "читать" из строки так же, как мы читаем из `std::cin`.
* `while (ss >> num)`: Цикл, который будет извлекать из строкового потока числа, разделенные пробелами, пока они не закончатся.
* `try { ... } catch(...) { ... }`: Блок **обработки исключений**. Код в блоке `try` выполняется. Если в нем происходит ошибка (например, `std::stoi` не может преобразовать "abc" в число), выполнение прерывается и переходит в блок `catch`. Это защищает программу от аварийного завершения.
* `pipes.emplace_back(...)`: Более эффективная версия `push_back`. Она создает объект прямо в памяти вектора, передавая аргументы в его конструктор, вместо того чтобы сначала создавать временный объект, а потом копировать его.
* `next_pipe_id = std::max(next_pipe_id, id + 1);`: Функция `std::max` возвращает большее из двух чисел. Мы используем её, чтобы после загрузки из файла счетчик `next_pipe_id` всегда был больше самого большого ID из загруженных.

#### `main.cpp` — Точка входа

Самый простой файл, его задача — запустить процесс.

* `SetConsoleOutputCP(65001);` / `SetConsoleCP(65001);`: Функции из `windows.h` для установки кодировки UTF-8 в консоли Windows. Это позволяет корректно отображать и вводить кириллицу.
* `Manager manager;`: Создание единственного экземпляра класса `Manager`.
* `while (true) { ... }`: Главный цикл программы (event loop), который работает, пока пользователь не выберет выход.
* `switch (choice) { ... }`: Конструкция, которая выполняет разный код в зависимости от целочисленного значения `choice`. Она более читаема, чем длинная цепочка `if-else if`.
* `case 1: manager.addPipe(); break;`: Если `choice` равен 1, вызывается метод `addPipe()` у объекта `manager`. `break;` необходим, чтобы выполнение вышло из `switch` после завершения `case`.
* `default:`: Этот блок выполняется, если `choice` не совпал ни с одним из `case`.

## 🏛️ Архитектура и ключевые концепции

Этот раздел предназначен для более глубокого понимания принятых проектных решений — идеально для защиты проекта.

### Объектно-ориентированное программирование (ООП)

Проект полностью построен на принципах ООП, что является шагом вперёд по сравнению с использованием простых структур.

1.  **Инкапсуляция:** Данные классов (`Pipe`, `CS`) объявлены в `private` секции. Это значит, что доступ к ним напрямую невозможен. Взаимодействие с объектом происходит только через `public` методы (геттеры и сеттеры). Это защищает данные от случайного или некорректного изменения и делает код более надежным. Мы предоставляем "пульт управления" объектом, скрывая его внутреннее устройство.

2.  **Абстракция:** Пользователю `Manager`'а не нужно знать, как именно хранятся трубы (в векторе, списке или где-то еще). Он просто вызывает метод `manager.addPipe()`. Классы предоставляют простой интерфейс для сложных действий.

### Архитектурный паттерн "Менеджер" (Controller)

Класс `Manager` выполняет роль центрального контроллера. Он изолирует логику управления данными от логики пользовательского интерфейса (`main.cpp`). Это классический пример **разделения ответственности** (Separation of Concerns): `main` отвечает за "показать и спросить", а `Manager` — за "обработать и выполнить".

### Система валидации ввода

Вместо множества функций для проверки ввода используется единая **шаблонная функция** `getValidInput<T>`.

  * **Как это работает:** Она считывает всю строку целиком (`std::getline`), а затем использует `std::stringstream` для попытки преобразовать эту строку в нужный тип (`int`, `double` и т.д.). Ключевая проверка `!(ss >> remaining_char)` гарантирует, что в строке нет лишних символов после числа (например, ввод "99 op" будет отвергнут).
  * **Преимущества:** Уменьшение дублирования кода и универсальность.

### Сохранение и загрузка данных (Персистентность)

Выбран простой и надежный текстовый формат. Для каждого списка объектов сначала сохраняется их количество, а затем данные каждого объекта записываются **построчно**.

  * **Почему такой формат?**
      * **Надежность:** Легко отлаживать, так как файл можно прочитать глазами.
      * **Устойчивость к ошибкам:** Построчное чтение менее подвержено ошибкам парсинга, чем чтение данных, разделенных пробелами (особенно если в названии объекта есть пробелы).

### Логирование

Класс `Logger` отвечает за запись всех действий в файл `log.txt`. Он открывает файл в режиме дозаписи (`ios::app`) и добавляет к каждому сообщению точную метку времени с помощью библиотеки `<chrono>`. Это стандартный инструмент для отладки и последующего анализа работы программы.

## 🚀 Сборка и запуск

### Требования

  * Компилятор C++ с поддержкой стандарта C++11 или выше (например, g++).

### Компиляция

1.  Поместите все файлы (`.h`, `.cpp`) в одну директорию.
2.  Откройте терминал или командную строку в этой директории.
3.  Выполните следующую команду для компиляции:
    ```bash
    g++ main.cpp Manager.cpp Pipe.cpp CS.cpp Utils.cpp -o pipeline_manager.exe
    ```

### Запуск

После успешной компиляции в директории появится исполняемый файл `pipeline_manager.exe`. Запустите его командой:

```bash
./pipeline_manager.exe
```
